# 术语与语言细节：把技术边界写进英文

依据前述全文与[逐句精读](逐句与段落精读.md)整理。下表是后续英文写作的候选约定，不自动修改 `main.tex`，也不替尚未冻结的实现命名。英语例句均为原创教学示例，不是作者原句或本项目结论。

## 1. 先统一概念，再追求语言变化

|候选规范表达|首次解释与对应含义|需要避免的漂移|
|---|---|---|
|zoned namespace (ZNS) SSD|首次展开ZNS；名称采用本领域通常形式|不要照搬个别论文里的Zone Namespace等变体|
|zone cleaning (ZC)|主机侧有效数据复制并回收zone的维护|不能不加说明与设备内部GC互换|
|garbage collection (GC)|转述OAZA等原文时保留其名称，并说明所在层|引文称GC不意味着所有动作在控制器内|
|read refresh (RR)|当前稿已采用的名称；首次应解释项目阈值和维护粒度|read reclaim在部分文献含义接近，但引用时保留原文术语，不假定所有机制相同|
|compaction|LSM文件重组操作|不能译成compression或与ZC合并成一个步骤|
|compression|编码/压缩；正文说compression ratio时需核对实际比值含义|ColdMap的历史输出/输入比还可能包含合并后淘汰，不能只按字面认成纯编解码效果|
|read-hot data|被当前读热规则识别的数据；H定义依实际版本|不能把OR较大、更新频繁的数据也统一叫read-hot|
|Flush-origin class (W)|描述当前来源标签的候选写法；首次解释W如何取得|不用write-hot或short-lived替代未经验证的来源语义|
|predicted lifetime / observed lifetime|分别是模型估计和实际观测；明确起止事件|不为避免重复而互换predicted/actual|
|remaining lifetime|从指定决策/复制时刻到失效的剩余量|不等于从创建到失效的总寿命|
|coldness|ColdMap的未来失效代理；需注明具体模型|不能直接当低读取频率或真实秒数|
|key-range overlap|范围关系|不自动等于相同Key数量或重叠文件数量|
|overlapping ratio (OR)|转述OAZA时按其分子、分母展开定义|不替换成Jaccard或假定范围[0,1]|
|pivot SST / unpivot SSTs|转述ColdMap压实选择时解释两类文件角色|不是ZC中的victim zone|
|victim zone / migration destination|分别是待回收源区和迁移目标|不要把source、target、victim混用|
|new-file allocation / migration allocation|区分新写入申请与必要搬运申请|不要仅凭一个布尔字段名就称为文件首次创建|
|admission / allocation|分别是准入判断和目标/空间分配|准入拒绝不等于整次I/O失败|
|fallback path|首选目标不可用后的具体后续路径|fallback不自动保证成功、隔离或成本下降|
|open-zone limit / active-zone limit|首次分别解释约束的状态集合|Open与Active不能视为两个拼写版本|
|zone size / zone capacity|分别解释地址跨度与可写容量|统计分母不能靠文风随意互换|
|free space / invalid data / writable tail|分别说明空闲、无效与尚可追加尾部|无效数据不等于立即可写空间|
|zone reset / physical block erase|逻辑接口动作与物理介质动作|少Reset不能直接写成已测得寿命延长|
|copied bytes / committed mappings|实际复制开销与成功安装映射分别核算|撤销复制仍可能产生实际I/O，不能因映射未提交就删掉成本|
|application latency / device latency|分别定义测量起止点与层次|fsync、文件操作总耗时不等于NAND介质延迟|
|controlled execution / concurrent execution|说明实际提交顺序、后台路径和并发度|受控实验不能只换一个形容词就代表正常并发性能|
|repeatability / robustness / variability|分别说明重复条件、扰动范围和离散对象|跨负载离散不能直接命名成重复运行方差|

H/W/HW、池大小K、阈值及程序身份的最终定义仍须对照冻结实现；本轮不凭阅读其他论文替本项目补定义。

## 2. 动词不是可以随意替换的同义词

|表达|它具体声称什么|使用时先检查什么|
|---|---|---|
|define / denote|规定术语或符号|是否给单位、集合和起止事件|
|record / measure / observe|分别强调记录、测量、观察到|观测点、采样与信息完整性|
|estimate / predict / approximate|估量、预测未来或近似求解|输入来源、误差与未知项|
|model / simulate / emulate|模型化、运行模型或模拟某系统的可见行为|论文具体对象与实现层；不机械把三者都翻成完全复现|
|select / rank / filter|选中、排序、筛除|筛过后是否还需安全/资源检查|
|maintain / update / preserve|维护结构、修改状态、保持某性质|哪个状态在变，哪个条件被保持|
|reduce / avoid / defer|降低总量、避免某动作、把动作推迟|观察窗口结束后是否仍有未偿还维护|
|suggest / indicate / support|通常是推断或支持某解释|三者没有脱离上下文的固定强度排名；需要看宾语主张|
|show / demonstrate|可用于直接呈现观察或演示能力|展示的是功能、测量关系还是已排除替代解释|
|confirm / establish|较强的证据认定|是否有独立验证、完整定义和适用边界|
|ensure / guarantee|对某性质作确定承诺|适用前提、失败路径与覆盖范围；不能只凭一次成功|
|eliminate|消除对象，通常意味着该口径下为零|计量范围与零值是否真实成立|
|aim to / seek to|方法或研究的目标|不能当成结果句使用|

不要把一个简单的show/suggest/confirm阶梯当作机械改词表。句子声称什么、证据支撑到哪里，比动词单独的词典解释更重要。

## 3. 时态、语态与情态：按句子功能选

方法的稳定规则可用现在时，某次已经完成的实现或测量可用过去时，图表当前展示什么常用现在时。这是常见选择，不是绝对模板；已发表文章用现在时介绍自身实现也自然。

原创教学例句：

- `The selector ranks eligible zones by the estimated cost.` 描述算法规则，不能据此推出估计准确。
- `We measured the copy volume after each cleaning cycle.` 描述做过的测量；若没有真实运行不能使用。
- `Figure X reports the copied bytes for the evaluated workloads.` 描述图的内容；Figure X是占位符，不是现有结果图。

主动语态适合交代谁决定、谁写入；被动适合让数据或状态成为段落主题。不是全用主动就更好，也不是删掉we就更客观。`The mapping is committed`若隐藏了关键执行者与时机，就需要补具体层次。

`can`可能表达能力，也可能表达某种可能性；`may`通常保留不确定；`will`可能是确定流程，也可能只是预测宾语里的未来时。先检查它修饰哪一层命题，不机械替换。

## 4. 冠词、指代与修饰语：小词可以改变算法范围

|语言细节|应怎样判断|为什么影响技术含义|
|---|---|---|
|a / the / 无冠词复数|首次引入可用a；已定义具体对象常用the；泛指集合可用复数|the victim暗含已确定对象；a candidate只说明某候选|
|a zone / each zone / all zones|一个实例、逐区规则、集合全称|不能把对实例的解释改成全称保证|
|the selected zone / a selectable zone|已选中与具备资格|候选合格不意味着实际发生复制|
|this / these / it / which|检查唯一、紧邻且语义正确的先行词|一个段落有候选、源、目标时，it很容易指错|
|only / already / remaining|分别限制集合、时间阶段和剩余量|删掉这些词可能改变输入范围或寿命定义|
|under / during / after / until|条件、持续阶段、先后关系、终止条件|after copying与after mapping commit不是同一个安全点|
|by / based on / according to|分别说明手段、依据或规则|based on说明信息输入，不代表该输入已被验证可靠|

原创教学例句：`After the mapping is committed, the source reference is released.` 这只是说明如何精确描述先后关系，不声明本项目所有路径都已满足它；真实正文必须回代码核验。

分词短语也要有清楚主语。`Using the snapshot, the selector ...`能说明谁使用快照；如果接一个与该动作无关的主语，读者会误解操作归属。普通完整让步句可用`although`接从句，`despite`通常接名词或动名词，避免误写despite of。英语也允许缩减让步结构，如C01；应核对省略的主语和谓语，不能把上述习惯当作绝对禁令。

## 5. 长句与段落衔接：把信息关系写出来

一个方法段落可依次回答“对象是什么—为什么需要—怎样处理—下一步用什么”。已经解释过的对象适合作为下一句主语，新增状态放在谓语之后。不要用一串Moreover/Furthermore掩盖操作之间没有说清的关系。

原创教学例句，两句只演示信息承接：

`The allocator returns a candidate zone. The caller then checks whether that zone has sufficient writable capacity.`

第二句保留candidate身份，说明分配建议之后仍有容量检查。它不是本文代码的替代规格。正式写作时还要根据真实接口判断检查发生的位置，不能为了句子好读就移动执行顺序。

并列项保持相同语法层次，如selecting、copying、resetting同作步骤；但并列语法也不能掩盖三步的依赖。遇到条件、例外和失败处理过多时，拆句或用伪代码比堆一个从句更清楚。

## 6. 数值比较：句子必须携带指标、基线与范围

以下全是**示例数据，仅用于说明**：假设Policy A复制100MB，Policy B复制80MB，则B的复制量相对A减少20%，归一化值为0.8。不能写成减少到20%，也不能叫吞吐提高20%。

若示例吞吐从100变为125MB/s，则是提高25%、达到基线1.25倍；延迟从100变为80μs则是降低20%。二者的倒数关系不能只凭数字相同就套用。比例从20%变为15%是下降5个百分点，或相对下降25%，两种说法必须区分。

- `by`通常跟变化量，`to`通常跟终值；数字、单位和方向一起核对。
- `up to`报告极值，不等于平均，也不能暗示每个负载都达到。
- `on average`需要说明平均哪些对象、怎样加权；跨负载平均不等于跨重复组平均。
- `normalized to`必须给基线；不能只在正文某处说“越低越好”而让图中1的含义不明。
- `respectively`依赖明确顺序；对象多、指标多时拆句或用表。
- `significant`在系统论文中有时表示幅度较大，但若容易被理解为统计显著，应报告检验或改为具体幅度；不能只换成substantial就补足缺失证据。

## 7. 不值得照搬的“论文腔”

原文里出现过的meticulously、intelligent、negligible、accurate、robust、eliminate等词，不因为发表就成为默认写法。先问它们改变了什么可检验的主张：精度怎样定义、开销占什么比例、鲁棒针对什么扰动、消除的计量范围在哪里。

也不为词汇丰富而把system、framework、scheme、policy、mechanism轮换指同一个对象。框架、策略与具体算法承担的范围可能不同。标题与方法名尽量稳定，普通动词保持自然；不追求每句都以We开头，也不追求彻底隐藏执行者。

## 8. 后续每个英文段落的检查顺序

1. 这句是在定义、说明方法、报告事实还是解释？原始依据在哪里？
2. 主语、动作、对象是否明确，术语是否与前文同义同名？
3. 输入是测得、估计还是预测？是否遗漏条件、时间窗或比较基线？
4. 情态词与show/confirm/ensure等谓语是否超出证据？
5. this/which/only/by/to等小词有没有改变指代、范围或数值关系？
6. 删去形容词后是否仍有实质信息？若没有，应补证据或删句。

这套检查用于把真实研究写准确，不替代研究判断；当前只建立语言准备资料，不在这里生成可冒称已完成实验的正文。
