# 三篇全文读完后，怎样比较它们与我们的课题

本文件是阅读后的分析与写作建议，不是论文正文，不是新的算法或实验授权。原文定位、公式手算与证据缺口见单篇笔记。

## 1. 最容易混淆的是“在哪个时刻回答什么问题”

|比较维度|OAZA / OAZA-GC，TACO2025|ColdMap，ICS2026|ZARC，DaMoN2026|本项目需要说清的事|
|---|---|---|---|---|
|主要决策|分配到哪里；一次清理多少区及选谁|必须清理时，根据未来compaction近似来选区|组合放置、清理与空区策略|新写入和必要迁移的准入、目标及普通回退；GC/RR各自职责|
|预测/使用的信息|层级、邻层OR、有效比例、标签、阈值|快照元数据、compaction规则、历史输出比例与频率|策略、层级、配置、空间与磨损信息|真实H来源、Flush-origin W来源、RC及资源；不能补成寿命真值|
|“冷”的主要语义|不易很快被重写/压实|未来较不易被compaction失效|取决于所选策略|区分读热和失效寿命，二者可不同|
|关键代价|搬运量、回收数量与WAF|预测误差、构造开销与搬运|组合与配置的相互代价、前进条件|ZC+RR累计实际搬运、末态空间、资源与应用性能|
|本文证据形态|多放置/多GC的控制因素比较|预测—真实存活—性能—敏感性多层验证|初步仿真、失败完成情况和组合权衡|以真实归档为准，目前不能从他文代填收益|

来源：[OAZA期刊版](https://doi.org/10.1145/3721287)、[ColdMap](https://doi.org/10.1145/3797905.3807851)、[ZARC作者原文](https://subhadeep.net/assets/fulltext/ZARC_Re-inventing_Zone_Allocation_for_LSMs_on_ZNS_SSD.pdf)。

三者不是简单的“旧方法逐代更强”。OAZA改放置并配套GC，ColdMap在给定放置上重点处理清理选区，ZARC探索配置与策略组合。基线对比应说明哪些因素保持一致、哪些属于方法本身，不能为了方便就把所有方法改成同一清理数量或同一分配器。

## 2. 可以学习的是论证链，不是照搬章节名

OAZA的链条是：level标签不足 → OR进一步区分 → 分配与GC配合 → 固定GC比较放置、固定放置比较GC → 用受害区组成解释复制量。

ColdMap的链条是：放置仍留混合 → 历史冷度在compaction后失效 → 运行时快照模拟 → 按文件大小聚合并选区 → 用实际后续存活验证预测 → 报告跨度/权重/开销和泛化范围。

ZARC的链条是：空间受限的推进问题 → 多个策略相互作用 → 模块化组合与回退 → 改配置后优胜策略变化 → 明示初步证据与未来计划。

对我们来说，不能把实施日志的先后顺序当论文结构。更好的做法是从一两个真实失效现象出发，每个现象对应一个必要设计选择，再让实验分别回答这些选择是否有效。

## 3. 现在不能预先宣称的贡献

- 不能说“首次按应用特征放置、首次将放置与GC结合、首次进行成本选区”；这些已有明确工作。
- 不能说“已有工作都只用层级标签”；OAZA的邻层OR与ColdMap的模拟已经超出这一范围。
- 不能把Flush-origin W改名为准确短寿命/写热预测；它与OAZA的OR、ColdMap的失效冷度不是同义词。
- 不能只用RR下降作为“总维护下降”的证据，也不能用少Reset替代物理磨损或寿命验证。
- 不能用本文的文献比较替代对SWEEP的全文核查：读热/写热共置已有线索，仍需认真核对边界。

“受限资源下的协同准入、迁移与回退如何影响ZC+RR净成本”可作为待验证的研究焦点；它是否足以成为最终贡献，取决于对照和真实证据，尚未认定。

## 4. 写作前应备齐的最小证据，而非立刻开跑

|想写的主张|应先有的证据|从本批阅读得到的提醒|
|---|---|---|
|某类共置是有效机会|实际进入、失效、必要RR发生的时间关系|相似标签/OR只是代理，应检查真实后续行为|
|准入或回退改善了成本|相同可比条件下，目标变化与逐笔复制/映射/Reset|不能仅凭一次拒绝申请或少一轮维护就归因|
|模型判断有效|模型分数之外的真实结果，如实际存活或避免的搬运|避免像自评分那样形成循环验证|
|全局收益为正|ZC、RR分项及总量，收尾未偿还维护、空间和性能|控制因素的比较比单张总吞吐图更有说服力|
|结果可推广|明确配置、负载、并发及模型范围|初步受控结果不自动代表真实并发或全部商用SSD|

这张表用于写作材料核查，不更改现有实验流程，不自动加Greedy重复组，不要求当前补跑论文里出现的所有配置。
